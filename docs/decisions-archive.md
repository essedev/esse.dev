# Decisions - archive

Entries of `docs/DECISIONS.md` that are no longer active. The numbering is the global one:
the `#N` references stay valid. #5, #7, #8 and #9 were suspended with the return to the
base style (Cycle 10) and their subject no longer exists in the Astro site; they remain
intact on the `restyle/laboratory` branch.

## #4 - A single navigation surface, `fixed` bar

**Status:** superseded by #10 (Cycle 11): with Astro there is no `overflow-x: hidden` on the container, the header is `sticky` and the floating nav does not exist

The floating nav, which duplicated the navbar, was removed; persistent controls go in the
chassis (`Chassis.svelte`). The bar is `fixed` and not `sticky`: `overflow-x: hidden` on
body and container (needed by the 300vw grid) makes the ancestor the scrollport and
sticky would never attach. Rejected: floating nav + navbar, sticky.

## #5 - Project listing at two densities, no pagination

**Status:** suspended on `restyle/base` (Cycle 10), was active (Cycle 9, block 4)

In progress and completed as cards with an image (showcase), archived and ideas as a
one-line typographic index (`utils/shelf.ts`, `EntryIndex`). The project listing is not
paginated: pagination would cut the two densities in half and the collection stays small
by curatorial choice. Articles stay paginated. Rejected: a single paginated grid of
cards.

## #7 - Favicons generated by script, outputs committed outside the build

**Status:** suspended on `restyle/base` (Cycle 10), was active (Cycle 9, block 4)

All sizes (svg, ico, 96px, apple-touch, 192/512, maskable) come out of
`scripts/generate-favicons.ts` from a single drawing, so the set does not diverge. Unlike
the OG images the outputs are committed and the script is not in the `pnpm build` chain:
it is rerun by hand with `pnpm generate-favicons` when the drawing or the default accent
changes. Rejected: hand-prepared files per size (the old set had diverged).

## #8 - Tokens and materials: no hand-written visual value in components

**Status:** suspended on `restyle/base` (Cycle 10), was active (Cycle 9, block 5)

Radii, lines, surfaces and mono sizes live as tokens in the `@theme` and every
container, chip, field or label uses a class of `@layer components` (`.panel`, `.chip`,
`.field`, `.label`, `.key*`, `.section`). Before, each component chose its own border
opacity and radius: eleven radii and eight borders for the same concept. One more class
costs a line; one more value costs coherence. Rejected: guidelines written without
classes (they do not hold at the second component).

## #9 - Device with a screen: hardware outside, software inside

**Status:** suspended on `restyle/base` (Cycle 10), was active (Cycle 9, block 5), replaces the first version (keycaps everywhere)

The chassis is a physical object: shell and keycaps (rail, tongue, LED, back-to-top,
navbar band). The screen shows software: panels, buttons, chips and fields are flat and
depth is only light. The first version brought the keycap inside the screen too and was
a skeuomorphism inside a skeuomorphism. Rejected: the "lit" key with a faint accent
background (at rest it read as disabled), the all-physical "control panel" (it does not
hold long prose or mobile, where the chassis is absent). The three systems compared are
in `docs/archive/concepts/system-variants.html`.
